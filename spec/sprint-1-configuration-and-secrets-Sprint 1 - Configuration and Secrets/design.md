## Enfoque

- **data_model:** Define `Settings` como dataclass inmutable en `src/mwangaza/config.py`, construido por `load_settings(env: Mapping[str, str] | None = None)`, sin Pydantic. Campos, tipos, defaults y perfiles validos quedan especificados: `environment`, `log_level`, rutas, paises habilitados, periodo de climatologia, credenciales GEE opcionales y `max_remote_pixels`.
- **external_contracts:** Todos los entrypoints publicos cargan `Settings`: API `/health`, dashboard y refresh. `/health` expone solo campos saneados: `environment`, `version`, `status`, `config_valid`, `enabled_countries`, `climatology_period` y nombres de variables faltantes, sin valores. Refresh `--dry-run` valida configuracion y no consulta servicios remotos; sin `--dry-run`, Sprint 1 sigue bloqueado con mensaje stub.
- **edge_cases:** Quedan definidos los casos invalidos: entorno desconocido, paises vacios o fuera de ISO3 IGAD permitido, anos no enteros, rango invertido, `max_remote_pixels <= 0`, rutas vacias, log level invalido y `MWANGAZA_GEE_PRIVATE_KEY_JSON` presente pero no JSON object valido. Placeholders como `replace-me` no bloquean en `test` o `demo`, pero cuentan como ausentes en `production`.
- **ui_states:** Dashboard muestra perfil activo, paises habilitados, periodo de climatologia y estado `configuration ok` o `configuration invalid`. Los errores son accionables y saneados, con nombres de variables o campos invalidos, sin secretos ni valores privados. En `production` invalido no continua mostrando datos ni claims operativos.

## Decisiones de la entrevista

- **adv-a2a34889a0:** Obligatorio por perfil: `production` requiere `MWANGAZA_GEE_PROJECT`, `MWANGAZA_GEE_SERVICE_ACCOUNT` y `MWANGAZA_GEE_PRIVATE_KEY_JSON` con valores no placeholder; `local`, `test` y `demo` no requieren variables privadas. Las variables publicas tienen defaults salvo cuando se proporcionan valores invalidos.
- **adv-a9c3efc157:** Privadas/secretas: `MWANGAZA_GEE_SERVICE_ACCOUNT` y `MWANGAZA_GEE_PRIVATE_KEY_JSON`. `MWANGAZA_GEE_PROJECT` es no sensible pero obligatorio en production. Publicas/no sensibles: `MWANGAZA_ENV`, `MWANGAZA_LOG_LEVEL`, `MWANGAZA_DATA_DIR`, `MWANGAZA_CACHE_DIR`, `MWANGAZA_DEMO_FIXTURE_DIR`, `MWANGAZA_ENABLED_COUNTRIES`, `MWANGAZA_CLIMATOLOGY_START_YEAR`, `MWANGAZA_CLIMATOLOGY_END_YEAR`, `MWANGAZA_MAX_REMOTE_PIXELS`.
- **adv-89eb3cf173:** Climatologia usa `MWANGAZA_CLIMATOLOGY_START_YEAR` y `MWANGAZA_CLIMATOLOGY_END_YEAR` como enteros de cuatro digitos con inicio <= fin. Paises usa `MWANGAZA_ENABLED_COUNTRIES` como lista separada por comas de ISO3 IGAD permitidos: `KEN,ETH,SOM,SDN,SSD,UGA,DJI,ERI`; se normaliza trim/mayusculas y se rechazan valores vacios o fuera de esa lista.
- **adv-6e46d45e6f:** Demo usa `MWANGAZA_DEMO_FIXTURE_DIR` como ruta local, default `./demo_data`. En Sprint 1 no se exige que la carpeta exista ni formato de fixtures, porque los fixtures demo pertenecen a sprints posteriores; el contrato es que el perfil `demo` no requiere credenciales GEE ni llamadas remotas y expone la ruta saneada.
- **adv-4ef053bd4a:** Cualquier configuracion invalida de entorno, fechas, paises, log level, rutas vacias, max pixels o JSON secreto mal formado debe fallar al construir `Settings` con `ConfigurationError`. Los entrypoints que cargan settings deben reflejar el error de forma saneada; nunca se ignoran valores invalidos ni se sustituyen silenciosamente por defaults.
- **data_model:** `Settings` sera un dataclass inmutable en `src/mwangaza/config.py`, construido por `load_settings(env: Mapping[str, str] | None = None)`. Campos: `environment` literal `local|test|demo|production` desde `MWANGAZA_ENV` default `local`; `log_level` string default `INFO`; `data_dir` Path desde `MWANGAZA_DATA_DIR` default `./data`; `cache_dir` Path desde `MWANGAZA_CACHE_DIR` default `./.cache/mwangaza`; `demo_fixture_dir` Path desde `MWANGAZA_DEMO_FIXTURE_DIR` default `./demo_data`; `enabled_countries` tuple[str, ...] desde `MWANGAZA_ENABLED_COUNTRIES` default `KEN,ETH,SOM,SDN,SSD,UGA,DJI,ERI`; `climatology_start_year` int desde `MWANGAZA_CLIMATOLOGY_START_YEAR` default `2001`; `climatology_end_year` int desde `MWANGAZA_CLIMATOLOGY_END_YEAR` default `2020`; `gee_project`, `gee_service_account`, `gee_private_key_json` opcionales desde las variables existentes; `max_remote_pixels` int default `100000000`. No usar Pydantic en Sprint 1 para evitar nueva dependencia.
- **error_states:** No debe fallar al importar el modulo. Debe fallar al construir `Settings` mediante `load_settings()` o al arrancar entrypoints que llamen a esa funcion. En `production`, si faltan variables obligatorias, levantar `ConfigurationError` con mensaje `Invalid Mwangaza configuration: <detalle>; missing required variables: VAR1, VAR2`. El mensaje debe listar nombres de variables, perfil activo y accion sugerida, pero nunca valores. CLI/refresh debe devolver codigo distinto de cero si no es dry-run seguro.
- **edge_cases:** Validar entorno desconocido, `enabled_countries` vacio o con codigos no ISO3 permitidos para IGAD, anos de climatologia no enteros, `climatology_start_year > climatology_end_year`, `max_remote_pixels <= 0`, rutas vacias, log level fuera de `DEBUG|INFO|WARNING|ERROR|CRITICAL`, y `MWANGAZA_GEE_PRIVATE_KEY_JSON` presente pero no JSON object valido. En `test` y `demo`, placeholders como `replace-me` se tratan como ausentes/no secretos reales y no bloquean. En `production`, placeholders cuentan como ausentes.
- **auth_secrets:** Privadas: `MWANGAZA_GEE_SERVICE_ACCOUNT` y `MWANGAZA_GEE_PRIVATE_KEY_JSON`; obligatorias solo en `production` junto con `MWANGAZA_GEE_PROJECT`. Publicas/no sensibles: `MWANGAZA_ENV`, `MWANGAZA_LOG_LEVEL`, `MWANGAZA_DATA_DIR`, `MWANGAZA_CACHE_DIR`, `MWANGAZA_DEMO_FIXTURE_DIR`, `MWANGAZA_ENABLED_COUNTRIES`, `MWANGAZA_CLIMATOLOGY_START_YEAR`, `MWANGAZA_CLIMATOLOGY_END_YEAR`, `MWANGAZA_MAX_REMOTE_PIXELS`. En `local`, `test` y `demo`, ninguna credencial real es obligatoria.
- **external_contracts:** Todos los entrypoints publicos deben cargar `Settings`: API `/health`, dashboard y refresh. API `/health` debe exponer solo `environment`, `version`, `status`, `config_valid`, `enabled_countries`, `climatology_period` y nombres de variables faltantes, sin valores. Dashboard debe mostrar perfil activo y estado de configuracion saneado. Refresh `--dry-run` debe validar configuracion y explicar que no consulta servicios remotos; sin `--dry-run`, en Sprint 1 sigue bloqueado con mensaje stub.
- **ui_states:** Si. El dashboard debe mostrar perfil activo, paises habilitados, periodo de climatologia y estado `configuration ok` o `configuration invalid`. Si la configuracion es invalida, mostrar mensaje accionable con nombres de variables o campos invalidos, sin secretos ni valores privados. En `production` invalido no debe continuar mostrando datos ni claims operativos.
- **rollback_compat:** Si. Mantener `MWANGAZA_GEE_PROJECT`, `MWANGAZA_GEE_SERVICE_ACCOUNT` y `MWANGAZA_GEE_PRIVATE_KEY_JSON` como nombres canonicos. Actualizar `.env.example` con nuevas variables publicas, comentarios de seccion publica/privada y placeholders no sensibles. No renombrar variables existentes en Sprint 1.
- **tests:** Tests minimos: `local` carga defaults sin secretos; `test` carga sin credenciales y no usa entorno real; `demo` carga con fixture dir local y no requiere GEE; `production` sin `MWANGAZA_GEE_PROJECT`, `MWANGAZA_GEE_SERVICE_ACCOUNT` o `MWANGAZA_GEE_PRIVATE_KEY_JSON` falla con `ConfigurationError` que lista nombres; placeholders fallan en production; fechas invertidas y pais invalido fallan; `repr(settings)`, `settings.to_public_dict()`, `/health` y logs de error no contienen valores secretos; variables actuales de Sprint 0 siguen aceptadas.
