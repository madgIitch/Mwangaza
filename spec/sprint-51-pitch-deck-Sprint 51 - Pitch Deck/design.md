## Decisiones de la entrevista

- **audience:** El público principal es el jurado del IGAD Hackathon 2026. Debe entender en pocos minutos el problema, la utilidad operativa, la diferenciación y la honestidad metodológica de Mwangaza.
- **duration:** Se configura una duración objetivo de 5 minutos, con tiempos por slide y margen para una breve transición a la demo. La duración queda documentada para poder ajustarla si las bases oficiales especifican otro límite.
- **narrative:** La historia seguirá problema → decisión que falta → solución → evidencia → demo → arquitectura → límites → siguiente paso. La idea central es que Mwangaza convierte observaciones satelitales en una cola operativa de episodios persistentes, sin presentar el ML experimental como certeza.
- **product_truth:** El deck debe reflejar el build final: 8 países IGAD, 121 ADM1 evaluadas, horizontes de 30/60/90/180 días, GEE como fuente operativa, NDMA como validación externa y FEWS NET como evidencia de impacto. No se presentará una página de reports que ya no forma parte del producto.
- **evidence:** Las cifras deben salir del estado materializado y de los backtests versionados del repositorio. Toda cifra simulada, experimental o dependiente de un corte temporal se etiquetará explícitamente.
- **deliverables:** Se entregarán un PPTX editable, un PDF exportado, las capturas finales utilizadas y un README breve con orden, tiempos, demo story y fallback.
